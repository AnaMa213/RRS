### R1 — The red-signal escalation test never supplies a red signal

**Source:** blind-hunter + verification-gap. **Requirement:** G6 (green required). **Location:** `Assets/RoadRage/Tests/EditMode/Story540GridlockTests.cs:229–248`, helper at `:426`; production predicate at `JunctionCoordinator.cs:757`.

`ARedOrMissingSignalIsNeverRelaxedByTheEscalation` constructs a signal plan whose groups are Red, but calls `Batch`. That helper calls `Resolve(frame, reports, null, cycles)`: the frame carrying the phase states is absent. `SignalReason` therefore returns `SignalUnavailable`, which is the only reason asserted. Existing Story536 red/phase cases do not submit cycles and therefore do not execute the escalation branch.

For example, replacing only the escalation predicate with `SignalReason(...) != JunctionReason.SignalUnavailable` would still reject missing state, keeping this test green, while admitting Red and Yellow after ordinary rules refused the requests. This is a blind spot in validation of a required safety guard, not evidence that the current predicate is wrong.

**Correction:** pass an actual TrafficFrame containing Red, then Yellow, to a batch with a submitted cycle. Require `SignalStop`, `Exhausted`, and no effective escalation grant. Keep the existing absent-state case. A Green control case should establish that the scenario otherwise reaches the intended admission path.

### R2 — Strict Merge protection in escalation has no behavioral regression proof

**Source:** verification-gap. **Requirement:** G6 and AC2 (no conflict with a live grant, Merge included). **Location:** `Assets/RoadRage/Tests/EditMode/Story540GridlockTests.cs:251–267`, `:431–449`, model builder at `:531–544`; production predicate at `JunctionCoordinator.cs:760`.

The live non-member grant test uses `CrossingSource`, whose only conflict zone is Crossing. No escalation fixture submits a cycle in a Merge scenario. Story535 Merge fixtures exercise the ordinary policy without cycles. Moreover, `AssertGrantInvariant` accepts an incompatible pair if its zone is Merge and either record has `MergeGap`, including a pair containing `GrantedGridlockEscalation`. The ordinary 5.35 exception is broader than G6's escalation admission rule.

A regression weakening only escalation to ignore Merge conflicts would not affect these Crossing fixtures or the ordinary Story535 Merge tests. If an existing holder carries `MergeGap`, the reused invariant would also accept the forbidden pair. The current production code correctly calls the strict `ConflictsWithGrants` predicate; the finding concerns the missing proof that this distinction stays intact.

**Correction:** add a submitted-cycle scenario with a live grant incompatible in a Merge zone. Ensure ordinary processing does not already grant a cycle member, so G5 does not bypass escalation. Include a live holder originally admitted through `GrantedMergeGap`; assert no escalation grant. Make the test distinguish strict escalation admission from ordinary merge-gap admission, and assert the escalation-specific invariant without changing the normal 5.35 policy.
