# Journal de validation tooling

Ce journal conserve les preuves de setup pour l'Epic 0. Une ligne peut passer en `Pass` uniquement si les champs reproductibles sont renseignes : date de preuve, responsable, commande ou chemin UI, chemin/resume de preuve, validateur et resultat de validation. Les lignes externes restent `Not Started` tant qu'une installation, un compte, un service cloud ou un smoke test n'a pas ete prouve.

## Vocabulaire de statut partage

| Statut | Signification |
| --- | --- |
| `Not Started` | Aucune action ou validation confirmee n'a commence. |
| `In Progress` | Le setup ou la validation a commence, mais la preuve est incomplete. |
| `Pass` | La validation a reussi et la preuve est enregistree avec tous les champs reproductibles. |
| `Blocked` | Un bloqueur empeche la completion. |
| `Not Applicable` | La ligne est hors du chemin de setup choisi ; noter pourquoi. |

## Regles de preuve

- Pour passer en `Pass`, renseigner au minimum : date, responsable/acteur, commande ou chemin UI, chemin/resume de preuve, validateur et resultat de validation.
- Caviarder les Lobby ID, invites, tokens Steamworks/Relay, credentials, API keys, identifiants Unity et secrets avec `[REDACTED_TOKEN]`.
- Ne colle jamais de secrets, tokens complets, liens d'invitation utilisables ou credentials de service dans ce fichier.
- Si un secret atteint le repo, une capture committee ou l'historique Git, arreter la validation, purger la preuve, faire tourner ou revoquer le secret concerne, puis documenter la remediation sans recopier le secret.
- Prefere les captures, resumes de sortie commande, chemins Unity, extraits de lockfile packages et notes de smoke test re-verifiables.
- Les installations GUI, comptes, approbations de services et smoke tests sont manuels ou confirmes par l'utilisateur. Les agents valident les preuves apres coup.
- Toute modification de package ou version doit etre revue avant Epic 1.
- Si Unity `6000.6.0f1` ou Blender `5.2 LTS` est indisponible, marquer la ligne `Blocked`, noter la source consultee, la version disponible, l'impact et demander approbation avant tout fallback.
